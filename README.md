## 製品概要
SNSで政治に触れる若者に向けた、点在した意見を1か所に集め、俯瞰して考える場を提供するSNSアプリ

かつ、現状のSNSの問題を根本から解決する、これからの民主主義社会で必要不可欠なSNSアプリ

### 背景
2026年2月衆院選、有権者の43%がSNS・動画を参考に投票を行った。（[参考文献](https://www.jiji.com/jc/article?k=2026020800810&g=pol#goog_rewarded)）<br>
今後SNSを基に投票・政治的議論を行う層が過半数を超えさらに拡大していくのはまず間違いないだろう。

しかし、ここで問いたい。

**本当に現状のSNSに国の行方を左右させてよいのか**

SNSはその特性上、ユーザーの好みの投稿が表示される。同じ議論が別々の場所に分散し、それぞれ偏った意見となっていることが少なくない。

これからの民主主義には**全体を俯瞰して見ることができるSNSの仕組み**が必要不可欠である。



### 製品説明（具体的な製品の説明）

**Rightsは、論点ごとに議論を一か所に集め、賛成・反対の理由と投票結果を見比べながら、自分の考えを深められる政治議論SNSである。**

ユーザーは関心のあるトピックの問いに対する賛成・反対の意見を一つの画面で確認することができる。それをもとに自分の立場を5段階の投票を通して考える機会を提供する。伝えたい意見があれば、投稿やコメントで主体的に参加することができる。
投票結果は投票前に表示されず、まず自分で考える機会を設け、無意識に意見が多数派に流されるのを防ぐ。また、納得した投稿へのリアクションである「なるほど」により、良い意見が代表意見として表に抽出される。さらに、政治用語をその場で調べられる辞書機能や、動画から投票・議論へ進む「今日のテーマ」を通じて、政治に詳しくない人でも参加できるようにする。

### 特長

#### 1. 同じ問いの賛否を一か所で比較することで、全体を俯瞰できる

#### 2. 投稿しない層の意見を5段階の投票によって反映できる

#### 3. いいねや投票の数による正しさのバイアスを排除する


### 解決出来ること
既存のSNSでは、自分と似た意見だけが表示されやすいのにもかかわらず、そこにある意見がすべてであると勘違いし、バイアスに気づけないまま自分の意見を持ってしまう問題を解決する。情報源としてのSNSの価値を高める。


### 今後の展望
今後は、ユーザーが多様な意見に触れ、自らの考えを深められるよう、以下の機能の導入を検討する。

1. **意見の表示アルゴリズムの工夫**
    
    みんなの意見を閲覧するページでは、自分と同じ意見と異なる意見の表示割合を調整できる機能を設ける。また、これまで触れていない観点を優先的に表示し、新たな視点から議論を捉える機会を提供する。
    
2. **議題の中立性の評価**
    
    AIによる判定やユーザーへのアンケートを通じて、議題の表現が特定の立場へ誘導するものになっていないかを確認する。これにより、問いの提示方法によってユーザーの意見に偏りが生じることを防ぐ。
    
3. **暴言・誹謗中傷への対策**
    
    AIが文脈を踏まえて投稿内容を判定し、暴言や誹謗中傷を含む投稿を制限する。悪質な投稿にはペナルティを設け、安心して議論に参加できる環境を整える。さらに、単なる非難にとどまらず、主張の根拠を論理的に示す建設的な対話を促進する。
    
4. **複数アカウントの作成制限とbot対策**
    
    電話番号認証などを活用し、同一人物による大量のアカウント作成やbotの利用を抑制する。これにより、組織的な投稿や投票による情報操作を防ぎ、議論の信頼性を高める。
    
5. **AIによる議論・トピックの推薦**
    
    自分の悩みがどの分野に該当するかわからないユーザーに対し、AIとの対話を通じて関連するトピックや問いを紹介する。また、考えを整理したい、さらに深めたいユーザーには、相談内容に関連する議論や意見を提示する。例えば、自分と異なる立場の意見交換や、年齢・性別などの属性が近いユーザーの意見を参照できるようにし、考えを深める手がかりを提供する。
    
6. **関心や考えに基づく政党の提案**
    
    投票や閲覧の履歴からユーザーが関心を持つ分野を分析し、投票・投稿の内容をもとに、考えに近い政策を掲げる政党を提案する。その際は、提案の根拠や各政党との共通点・相違点を示し、ユーザー自身が比較・判断できるようにする。

### 注力したこと（こだわり等）

- **課題が解ける場面を、一つの画面で示すこと**
    
    設問、賛否の理由、投票をまとめ、ユーザーが「問いを知る・理由を比較する・自分の立場を表す」という流れを実際に操作できるようにしました。
    
- **読む人も参加者になれること**
    
    投稿を必須にせず、5段階の投票から参加できるようにしました。辞書や動画も組み合わせ、政治の知識や発信経験による参加のハードルを下げることに取り組みました。
    

    

## 開発技術

### 活用した技術

![アーキテクチャ図](./docs/architecture.svg)

概要図・システム構成図・データ構造などの詳細は [docs/architecture.md](./docs/architecture.md) にまとめている。

#### API・データ

- **Supabase Auth / PostgreSQL / Storage**
    
    認証、議題・投稿・コメント・投票・リアクションの保存、動画配信に利用しています。データベースではRLSによるアクセス制御を実装しています。
    
- **Next.js Route Handlersによる独自API**
    
    認証、議題取得、投稿、投票などの処理を実装し、入力検証とエラーレスポンスを管理しています。
    
- **カテゴリ・設問・政治用語の初期データ**
    
    JSONで管理し、議論の入口となるトピックと、理解を支える用語解説に利用しています。
    

#### フレームワーク・ライブラリ・モジュール

- **Next.js 16.4.2 / React 19.3.0 / TypeScript**：画面とサーバー側APIの実装。
- **Tailwind CSS 4 / CSS**：画面のレイアウトとスタイル。
- **Supabase SDK**：認証・データベース・Storageへの接続。
- **ESLint / Node.js標準テストランナー**：静的解析と、入力検証・認証フロー・データ取得処理などのテスト。

#### デバイス

- スマートフォンのWebブラウザー
- PCのWebブラウザー

専用機器を必要とせず、日常的に使うブラウザーからアクセスできる構成です。

### 独自技術

#### ハッカソンで開発した独自機能・技術

- **賛否比較と5段階投票を統合した論点画面**
    
    同じ問いに対する賛否の理由と投票をまとめ、投票後に結果の比率を表示します。課題として掲げた「比較の難しさ」に直接対応する部分です。
    
   [論点まとめカード](app/src/app/components/topic-summary-card.tsx)／[投票結果の表示](app/src/app/components/vote-result-bar.tsx)
    
- **評価時点の立場を保持するリアクション基盤**
    
    リアクション時点の投票内容を保存し、賛成側・反対側それぞれからの評価を集計します。投票とリアクションが同時に更新される場合の整合性にも配慮しています。意見の自動抽出・画面への反映は今後の実装対象です。
    
    [立場の保存・集計](supabase/migrations/20261024030000_add_reaction_vote_snapshot_and_aggregation.sql)／[同時更新の制御](supabase/migrations/20261024040000_allow_unvoted_thread_reactions.sql)
    
- **議論の文脈を保ったまま調べられる辞書レンズ**
    
    用語にレンズを重ねて解説を表示し、読む画面を離れずに理解を補えます。
    
    [辞書レンズ](app/src/app/components/dictionary.tsx)
    
- **動画・投票・議論をつなぐ参加導線**
    
    「今日のテーマ」の動画視聴から、その問いへの投票、議論の閲覧へ進めます。
    
    [今日のテーマ画面](app/src/app/screens/daily-theme-screen.tsx)
