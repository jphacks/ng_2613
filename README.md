## 製品概要

### 背景(製品開発のきっかけ、課題等）

**SNSには政治の意見があふれているのに、同じ問いに対する賛成・反対の理由を見比べることは難しい。** 私たちは、この情報の多さと比較の難しさのギャップに着目しました。

既存のSNSでは、一つの政策についての議論が投稿やコミュニティごとに分散しています。また、興味に合う投稿が優先されることで、自分に近い意見に触れやすく、別の立場が何を重視しているのかを把握しにくくなっています。

特に、政治に関心を持ち始めた人や、投票前に複数の立場を比較したい人にとって、判断材料を自力で集めて整理する負担は小さくありません。

そこで私たちは、個人に情報収集の努力を求めるだけでなく、**議論を集める単位と見せ方を変える**ことで、この課題に取り組みました。

### 製品説明（具体的な製品の説明）

**Rightsは、論点ごとに議論を一か所に集め、賛成・反対の理由と投票結果を見比べながら、自分の考えを深められる政治議論SNSです。**

ユーザーは関心のあるトピックから設問を選び、同じ問いに対する賛成・反対の意見を一つの画面で確認できます。自分の立場は5段階の投票で表明でき、理由を伝えたいときには投稿やコメントで参加できます。

まず自分で考えて投票し、その後に投票結果の分布を確認する流れを設けています。さらに、政治用語をその場で調べられる辞書機能や、動画から投票・議論へ進む「今日のテーマ」を通じて、政治に詳しくない人の参加も支援します。

### 特長

#### 1. 投稿を追う必要なく、同じ問いの賛否を比較できる

議論を設問ごとにまとめ、賛成・反対の意見を同じ画面に表示します。

「この政策に賛成か」という問いに対して、賛成する理由と反対する理由を続けて確認できるため、別々の投稿を探して比較する負担を減らします。**論点を共通にすることで、立場の違いだけでなく、その背景にある理由へ目を向けられる設計**です。

#### 2. 書き込まない人も5段階の投票で参加できる

文章を書かなくても、反対から賛成までの5段階で意思を表明できます。強い賛否だけでなく、中間の立場も選べます。

投票後は、投稿された理由と参加者の投票分布を見比べられます。発信に慣れた人だけでなく、まずは読むことから始めたい人にも参加の入口を用意しました。

#### 3. 数の多さに流されず、内容の真の理解を促す

投稿には「なるほど」のリアクションを付けられますが、評価数は画面に表示しません。また、投票結果の比率は投票後に表示し、他の人の選択を見る前に、自分の立場を選ぶ流れにしています。これは、ついつい多数派の意見に流されてしまうのを防ぎ、本当の自分の考えに向き合う機会を用意するためです。

分からない用語には辞書レンズを重ね、その場で意味を確認できます。政治への興味を持ち始めた人が政治について考えるハードルを下げる仕組みを作りました。

### 解決出来ること

Rightsがまず取り組むのは、**「異なる立場の判断材料を探して、比較することの難しさ」**です。

- **議論が分散していて比較しにくい**
    
    同じ設問の下に賛成・反対の意見をまとめ、双方の理由を確認できます。
    
- **投稿する人の意見だけでは、参加者の考えが分からない**
    
    投稿に加えて5段階の投票を設け、書き込まない参加者も意思を表明できます。
    
- **政治用語が分からず、議論を読む途中で止まってしまう**
    
    画面内の辞書で意味を確認し、議論を読み続けられます。
    

こうした機能を通じて、複数の視点を踏まえて判断するための環境を提供します。偏りの軽減や理解の深まりについては、今後ユーザー検証で効果を確かめます。

### 今後の展望

**第一に、立場をまたいで評価された意見を見つける仕組みを実現します。** 賛成・反対の両方から「なるほど」と評価された意見を抽出し、論点ごとのまとめに反映する構想です。現在は、リアクション時点の投票内容を保存し、立場別に評価を集計するデータベース側の基盤を実装しています。

第二に、デモ表示となっている年代・性別の統計を、プライバシーに配慮した実データの集計へ発展させます。参加人数や回答者の構成を示し、アプリ内の投票結果を社会全体の意見と混同しにくい表示を目指します。

利用者の拡大に向けては、まず政治に関心を持ち始めた人や、投票前に政策を比較したい人を対象に検証します。「反対側の理由を説明できるようになったか」「投票だけでも参加しやすかったか」を確認し、議題・動画・用語解説を充実させます。あわせて、出典管理やモデレーションの運用を整えます。

### 注力したこと（こだわり等）

- **課題が解ける場面を、一つの画面で示すこと**
    
    設問、賛否の理由、投票をまとめ、ユーザーが「問いを知る・理由を比較する・自分の立場を表す」という流れを実際に操作できるようにしました。
    
- **読む人も参加者になれること**
    
    投稿を必須にせず、5段階の投票から参加できるようにしました。辞書や動画も組み合わせ、政治の知識や発信経験による参加のハードルを下げることに取り組みました。
    
- **今後の中核機能につながるデータ設計**
    
    「なるほど」を押した時点の投票内容を保存し、その後に立場が変わっても、評価当時の情報を保持します。立場をまたぐ評価を分析するための基盤として設計しました。
    

## 開発技術

### 活用した技術

#### API・データ

- **Supabase Auth / PostgreSQL / Storage**
    
    認証、議題・投稿・コメント・投票・リアクションの保存、動画配信に利用しています。データベースではRLSによるアクセス制御を実装しています。
    
- **Next.js Route Handlersによる独自API**
    
    認証、議題取得、投稿、投票などの処理を実装し、入力検証とエラーレスポンスを管理しています。
    
- **カテゴリ・設問・政治用語の初期データ**
    
    JSONで管理し、議論の入口となるトピックと、理解を支える用語解説に利用しています。
    

#### フレームワーク・ライブラリ・モジュール

- **Next.js 16.4.2 / React 19.3.0 / TypeScript**：画面とサーバー側APIの実装。
- **Tailwind CSS 4 / CSS**：画面のレイアウトとスタイル。
- **Supabase SDK**：認証・データベース・Storageへの接続。
- **ESLint / Node.js標準テストランナー**：静的解析と、入力検証・認証フロー・データ取得処理などのテスト。

#### デバイス

- スマートフォンのWebブラウザー
- PCのWebブラウザー

専用機器を必要とせず、日常的に使うブラウザーからアクセスできる構成です。

### 独自技術

#### ハッカソンで開発した独自機能・技術

- **賛否比較と5段階投票を統合した論点画面**
    
    同じ問いに対する賛否の理由と投票をまとめ、投票後に結果の比率を表示します。課題として掲げた「比較の難しさ」に直接対応する部分です。
    
    論点まとめカード／投票結果の表示
    
- **評価時点の立場を保持するリアクション基盤**
    
    リアクション時点の投票内容を保存し、賛成側・反対側それぞれからの評価を集計します。投票とリアクションが同時に更新される場合の整合性にも配慮しています。意見の自動抽出・画面への反映は今後の実装対象です。
    
    立場の保存・集計／同時更新の制御
    
- **議論の文脈を保ったまま調べられる辞書レンズ**
    
    用語にレンズを重ねて解説を表示し、読む画面を離れずに理解を補えます。
    
    辞書レンズ
    
- **動画・投票・議論をつなぐ参加導線**
    
    「今日のテーマ」の動画視聴から、その問いへの投票、議論の閲覧へ進めます。
    
    今日のテーマ画面を入れた部分をファイルリンク、またはcommit_idを記載してください。
